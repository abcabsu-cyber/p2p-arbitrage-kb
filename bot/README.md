# Бот P2P Study (Cloudflare Worker)

Бесплатный сервер для `@ptp_study_bot`: ответ на /start, проверка подписки на канал, рассылки.

## Запуск (один раз, ~15 минут)
1. Аккаунт на cloudflare.com (бесплатный).
2. Workers & Pages → Create → Create Worker → имя `p2p-study-bot` → Deploy → Edit code → вставить весь `worker.js` → Deploy.
3. Storage & Databases → KV → Create → имя `SUBS`. В Worker → Settings → Bindings → Add → KV namespace → переменная `SUBS`, выбрать созданное.
4. Worker → Settings → Variables and Secrets:
   - `BOT_TOKEN` (Secret): токен из BotFather (/mybots → бот → API Token)
   - `WEBHOOK_SECRET` (Secret): любая случайная строка из 20+ букв и цифр
5. Открыть в браузере `https://<адрес-воркера>.workers.dev/setup?key=<WEBHOOK_SECRET>` — должно показать `"ok":true` трижды.
6. Написать боту `/myid`, взять число, добавить переменную `OWNER_ID` (Variable) с этим числом.
7. Добавить бота администратором в канал (нужно для проверки подписки).

## Команды владельца (в чате с ботом)
- `/post` — рассылка о самом новом материале (первом в списке); `/post <id>` — о конкретном
- `/broadcast текст` — произвольная рассылка
- `/test текст`, `/post_test <id>` — то же, но только вам (проверка перед рассылкой)
- `/undo` — удалить последнюю рассылку у всех (Telegram разрешает в течение 48 часов)
- `/stats` — число подписчиков

## Оплата криптой (Heleket)
1. В кабинете heleket.com: Merchant UUID (настройки) и Payment API key. Кошелёк для вывода и (по желанию) авто-конвертация в USDT.
2. Worker → Settings → Variables and Secrets: `HELEKET_MERCHANT` (Secret), `HELEKET_KEY` (Secret). Необязательно: переменные `PAY_AMOUNT` (по умолчанию 4990) и `PAY_CURRENCY` (по умолчанию RUB).
3. Адрес для уведомлений Heleket подставляется автоматически (`https://<адрес-воркера>/pay/webhook`), в кабинете ничего указывать не нужно.
4. Команды владельца: `/paid` — сколько оплатили, `/grant <id>` — выдать доступ вручную.
Доступ открывается с 1 декабря 2026, длится 31 день, продление за 10 дней до конца.

## Закрытые материалы
Бот выдаёт статьи, картинки и данные только тем, кто открыл приложение внутри Telegram (проверка подписи `initData`).
- `POST /api/session` — обмен подписи Telegram на токен (действует от 24 до 48 часов: срок округляется до суток, чтобы ссылки на картинки не менялись в течение дня).
- `GET /c/bundle?t=<токен>` — всё для старта одним ответом (materials.json, products.json и тексты статей).
- `GET /c/content/...?t=<токен>` — выдача файла.
Источник файлов: если заданы `CONTENT_REPO` (например `abcabsu-cyber/p2p-content`) и секрет `GH_TOKEN` (fine-grained токен, только чтение), файлы берутся из приватного репозитория; иначе — с публичного сайта (как раньше).
Включение полной блокировки вне Telegram: в index.html `var STRICT = true`.

### Где что лежит теперь
- Публичный репозиторий (GitHub Pages): только оболочка приложения (`index.html`) и баннер входа.
- Приватный репозиторий `p2p-content`: все материалы (`content/`). Новые материалы публикуются туда.
- Блокировка вне Telegram включена (`STRICT = true`).

## Защита и резервные копии
- Лимиты запросов с одного IP (сессия, статус, создание счёта, выдача материалов, вебхук Heleket); при превышении ответ 429.
- Заголовки безопасности на всех ответах бота (nosniff, no-referrer, запрет встраивания).
- Запись подписчика в KV только при первом заходе (на бесплатном тарифе Cloudflare лимит 1000 записей в сутки).
- Резервная копия оплативших: команда `/backup` присылает JSON-файл владельцу. Автоматически раз в сутки: Worker → Settings → Triggers → Cron Triggers → Add → `0 * * * *` (каждый час: копия уходит один раз в сутки в 9:00 МСК, а каждый час обрабатываются заявки и окончания доступа в закрытый канал).


## Подписчики

- `/users` — список подписчиков файлом CSV (id, username, имя, дата, оплата)
- `/who <id>` — сведения о человеке
- `/ban <id>` — исключить: нет доступа к материалам, нет рассылок
- `/unban <id>` — вернуть

## Уведомления об оплате (отдельный бот)

Создайте второго бота в BotFather, нажмите в нём /start. Токен — в Cloudflare как Secret `NOTIFY_BOT_TOKEN`. Чат по умолчанию — `OWNER_ID` (или задайте `NOTIFY_CHAT_ID`, например id закрытой группы). Без этих переменных уведомления идут через основного бота.
Приходит: сумма, кто оплатил, товар, время (МСК), номер заказа, UUID и TXID, срок доступа; а также предупреждения о неполной оплате, сбоях и возвратах. `/order <номер заказа>` в основном боте — детали оплаты.

## Оплата через 2328 (my.2328.io)

Переменные Cloudflare: `PAY2328_PROJECT` (Variable, UUID проекта), `PAY2328_KEY` (Secret, **API key**, не Payout key). Если заданы оба, оплата идёт через 2328; Heleket остаётся запасным (`PAY_PROVIDER=heleket` переключает назад).
Callback URL в проекте 2328 не нужен: адрес `https://<worker>/pay/webhook2328` передаётся в каждом счёте. Подпись: HMAC-SHA256(base64(JSON без sign), API key). Доступ выдаётся при `paid` и `overpaid`; `underpaid`, `aml_lock`, возвраты дают только уведомление владельцу. Потерянный webhook добирается сверкой через `/v1/payment/info` при проверке статуса в приложении.

Проверка без оплаты: команда владельца `/test2328 [статус]` просит 2328 прислать синтетический webhook на наш адрес (по умолчанию `paid`; можно `underpaid`, `overpaid`, `aml_lock`, `refund_paid` и т. д.). Подпись проверяется, доступ не выдаётся, результат приходит от бота оплат.

## Страница участника привата

После оплаты раздел «Приват» в приложении заменяется страницей «Вы в привате» (дата окончания, как всё будет, кнопка «Подать заявку в закрытый канал», «Написать нам»; за 10 дней до конца появляется «Продлить»). Кнопки оплаты после оплаты нет.
Ссылка на канал: Variable `JOIN_URL` в Cloudflare (пригласительная ссылка с «Заявки на вступление»). Воркер отдаёт её только оплатившим, в ответе `/api/status`.

## Crypto Bot (Crypto Pay)
Secret `CRYPTOBOT_TOKEN` (токен из @CryptoBot → Crypto Pay → приложение). В настройках приложения → Webhooks → Enable, URL: `https://<worker>/pay/webhook-cryptobot`. Выбор способа оплаты в мини-аппе передаётся как `method: "cryptobot"` в `/api/pay/create`.

## Закрытый канал: приём и удаление автоматически
1. В закрытом канале включите «Заявки на вступление» у пригласительной ссылки; эта ссылка — переменная `JOIN_URL` (по ней работает кнопка «Подать заявку» в приложении).
2. Добавьте бота @ptp_study_bot администратором канала с правами «Добавление участников» (приглашения) и «Блокировка участников».
3. Переменная `PRIVATE_CHANNEL` — числовой id канала (вида `-100…`). Без неё автоматика выключена.
4. Откройте ещё раз `https://<worker>/setup?key=<WEBHOOK_SECRET>`, чтобы бот начал получать заявки (`chat_join_request`).
5. Cron Trigger `0 * * * *` (см. выше).

Как работает: заявку без действующей оплаты бот отклоняет и объясняет, как оплатить. Заявку оплатившего до 1 декабря запоминает и одобряет в первый час 1 декабря, после 1 декабря — сразу. Когда доступ закончился, бот убирает человека из канала (без вечного бана: после продления он снова подаёт заявку) и пишет ему, как продлить. `/revoke <id>` тоже убирает из канала. Владельца бот не трогает.

## Рассылки
`/cancel` — остановить идущую рассылку (текущая порция дойдёт, отправленное можно удалить через `/undo`). При ограничении Telegram (429) бот ждёт и повторяет сообщение один раз.

## Если 2328 недоступен
Если 2328 не смог создать счёт, а `CRYPTOBOT_TOKEN` задан, бот сразу выдаёт счёт Crypto Bot, чтобы человек не упёрся в ошибку.
